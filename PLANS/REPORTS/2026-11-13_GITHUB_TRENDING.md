## 專案 1：[shanselman/gputaskman](https://github.com/shanselman/gputaskman) (★ 2765)
- **語言**：`Python` | **說明**：A GPU task manager for Windows, Linux, and WSL: per-process VRAM, GPU activity, and LLM model/KV-cache insights (Windows AMD and NVIDIA).

## 1. 用途（有咩用）

| 面向問題 | gputaskman 提供的解決方案與創新亮點 |
|---------------|-----------------------------------------------|
| **GPU 資源透明化** – 開發者難以瞭解單一進程在 GPU 上佔用的顯存、計算量，特別是在 LLM 推理場景中（模型權重、KV 快取、部分卸載、量化等複雜分配）。 | • 基於 **NVML** 實現 **跨平台（Windows/Linux/WSL）** 的 **每進程 GPU 顯存** 與 **GPU 活動** 監測。<br>• 提供 **LLM 模型/KV-快取洞察**，可估算 llama.cpp 風格的內存佈局（部分卸載、KV 量化、滑動窗口注意力、多模型共用進程）。 |
| **多 GPU 後端支援** – 現有工具多偏向 NVIDIA，AMD 用戶缺乏替代方案。 | • 同時支援 **NVIDIA** 與 **AMD** 顯卡的 Windows 與 Linux 平台。 |
| **容器化環境的 GPU 監控** – 容器內進程的 PID 與宿主機 NVML 報告不一致，導致監控失準。 | • 提供 **容器 PID 轉換** 機制，將宿主機 NVML 報告的 PID 映射到容器內部的正確進程（需額外配置）。 |
| **輕量級執行** – 無需額外代理，純 Python + PyInstaller 打包，適合邊緣與雲端部署。 | • 單文件執行檔，無依賴，支援 **x64/ARM64** 架構（需指定 `--arch`）。 |

**核心痛點**：LLM 推理工作負載的 GPU 資源分配極不透明，導致資源浪費或飽和。gputaskman 通過將 NVML 數據與進程級細粒度對齊，填補了從「粗粒度 utilisation」到「細粒度內存佈局估算」的監控空白。

## 1. 用途（有咩用）

| 痛點 | 專案解決方案 | 技術亮點 |
|------|--------------|------------|
| **在純命令列環境中運行完整的 macOS GUI** – 無法在 headless 伺服器或 CI 管道中獲得真實的 macOS 桌面。 | 利用 Apple 虛擬化框架（Virtualization.framework）啟動一個真實的 macOS 客體系統，並將其視覺輸出轉為 terminal 圖形協議流。 | • **原生虛擬化** – 客體是真實的 macOS 安裝，支援所有系統級 API。<br>• **內嵌輔助程式** – 客體內的輔助程式捕獲螢幕快照並上報輸入事件（滑鼠、鍵盤），實現無需移動實體指標或修改剪貼板的精確控制。<br>• **Terminal 圖形協議** – 利用 Kitty 或 iTerm2 的圖形擴展，將遠端像素流直接渲染為 terminal 中的視窗。<br>• **代理命令傳輸** – 相同的輔助程式提供一個無狀態的命令執行管道，允許從外部 shell 發送 shell 命令到客體。 |
| **需要一個可重現、可回退的 macOS 測試環境** – 傳統的模擬器或容器無法提供真實的 macOS 版本和硬體級功能。 | 提供一個**單一命令安裝程式**（curl）來部署客體、輔助程式和 terminal 視圖器。客體是自包含的，無需 Apple 認證即可運行（自簽章）。 | • **無需認證的安裝** – 繞過 Apple 的 notarization 流程，但仍需用戶手動允許。<br>• **輕量級輔助程式** – 僅運行於客體中，減少主機上的攻擊面。 |
| **多代理人或自動化工作流需要一個可被遠端控制的 macOS 環境** – 現有 VNC/RDP 解決方案要麼缺少 GUI 輸入的精細控制，要麼需要額外的顯示器。 | 將 terminal-mac 視為一個**代理計算機**，代理可以發送 shell 命令、獲取螢幕快照，並在不影響主機的實際 macOS 會話的情況下觸發輸入事件。 | • **輸入隔離** – 輔助程式只影響客體的虛擬指標/鍵盤狀態，不影響主機。<br>• **螢幕快照 API** – 每幀螢幕快照都可通過輔助程式的簡單端點獲取，方便視覺反饋。 |

**核心創新**：將 Apple 虛擬化框架與 terminal 圖形協議和精細輸入代理服務器相結合，從而實現了一個*終端優先*的真實 macOS 客體，這在開源領域是前所未有的。

### 1. **用途** – 解決什麼核心痛點？

| 痛點 | 專案解決方案 | 技術亮點 |
|------|--------------|----------|

**核心價值**：將抽象的「技術棧描述」轉化為**即用型的、可執行的架構圖**，同時保持品牌標誌的準確性與視覺專業性。
