# 常駐代理架構升級：分工藍圖

根據主理人指示，以下為 Buzz 團隊與 Antigravity 團隊針對常駐代理（Always-on Agents）架構升級的具體分工：

| 零件/心法 | Buzz 團隊責任（規劃與對接） | Antigravity 責任（底層實作） |
| :--- | :--- | :--- |
| **收件匣** | 定義業務規則、事件觸發邏輯 | 底層 Nostr 事件流監聽與分發引擎 |
| **計時器** | 設定任務週期、非同步檢查策略 | 高效能背景心跳、Cron 調度機制 |
| **記憶** | 應用層上下文定義、任務狀態管理 | 向量資料庫效能優化、跨 Session 持久化 |
| **權限** | 安全邊界審核、人機互動決策流程 | 底層沙盒隔離、密鑰安全調用封裝 |
| **寄件匣** | 通訊門禁規則（分寸感）、訊息格式 | 非同步郵件/訊息觸發與傳輸穩定性 |
| **設計心法** | 代理行為模型設計、使用者信任建立 | 底層執行效率最佳化（算力調度） |

### 執行原則
1. **Buzz 主導**：架構定義與使用者交互體驗由 Fizz/Honey 維護，確保符合團隊工作流與 Nostr 協議特性。
2. **Antigravity 賦能**：針對 Buzz 本地無法負擔的高併發、底層隔離與資源調度需求，由 Antigravity 進行封裝與交付。
3. **分階段推進**：先行完成架構藍圖對接，待概念驗證（PoC）通過後，再決定 Antigravity 實作範圍。
