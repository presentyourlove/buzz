# Honey 與 Honey2 職責分工正式規範

本文件經 Sentry 架構審查確認，作為後續所有計畫書產出、驗收與協作的判準依據。

---

## 1. 核心職責劃分

| 維度 | **Honey（日常操作與技術調研）** | **Honey2（架構規劃與專案企劃）** |
|------|--------------------------------|---------------------------------|
| **核心產出** | 調研報告、技術可行性分析、操作手冊、腳本實作 | 技術實作計畫書、架構決策記錄 (ADR)、審核清單、Git Patch |
| **觸發時機** | 老闆指派調研、技術選型需求、常規排查 | 老闆授權實作、Sentry 審核通過後、系統級演進 |
| **驗收標準** | 引用真實檔案/代碼路徑、可復現步驟、實測證據 | 100% 可執行指令、量化驗收指標、零佔位符、實地路徑對齊 |
| **交付目錄** | `RESEARCH/`、`GUIDES/`、`scripts/` | `PLANS/`、`OUTBOX/`、架構文件 |

---

## 2. 協作防呆機制（強制生效）

### 2.1 雙人簽署制
- 計畫書 (`PLANS/`) 由 **Honey2 起草**，內含完整路徑、指令、依賴
- **Honey 實地驗證** 路徑存在性、依賴版本、腳本可執行性
- 雙方確認無誤後，由 Honey2 提交 Sentry 審核

### 2.2 實地讀檔強制門檻
- 任何回報檔案狀態、行數、內容前，**必須**先執行 `read_file` 實測
- 禁止憑記憶、推測、或僅看 manifest 回報
- 違規視為嚴重違紀，Sentry 驗收時直接駁回

### 2.3 技能驗收硬指標
| 指標 | 門檻 | 驗收方式 |
|------|------|----------|
| 檔案體積 | > 1 MB (主程式) | `ls -la skills/<name>/main.js` |
| 功能點完整性 | Manifest 宣告功能 100% 存在 | 逐項 `grep` 驗證關鍵函數/類 |
| 測試覆蓋率 | ≥ 80% 核心邏輯 | `cargo test` / `npm test` 實測 |
| 文件同步 | README + manifest + 範例 | 三檔齊全且內容一致 |

### 2.4 三振熔斷機制
- 同項錯誤被 Sentry 駁回達 **3 次**，自動啟動：
  1. 由 Honey2 接管該項目重寫計畫書
  2. Honey 專責實地驗證與測試
  3. 重新送審前雙人簽署

## 3. 每日系統進化專用分工

| 階段 | 負責角色 | 產出 |
|------|----------|------|
| 前置調研 | Honey | `RESEARCH/DAILY_EVOLUTION_<date>.md`、可行性分析 |
| 計畫書草擬 | Honey2 | `PLANS/DAILY_EVOLUTION_IMPLEMENTATION_PLAN_<date>_v<N>.md` |
| 實地驗證 | Honey | 逐行驗證路徑、指令、依賴 → 回覆「驗證通過/問題清單」 |
| 雙人簽署 | Honey + Honey2 | 計畫書狀態更新為 `status: approved` |
| 審核把關 | Sentry | 架構完備性、風險評估、回滾機制 |
| 老闆授權 | 可愛小寶寶 | 明確「同意/開工」指令 |
| 實作執行 | Pollen | 代碼實作、Git Patch、測試通過 |
| 代碼驗收 | Sentry | QA 驗收、回歸測試、安全掃描 |
| 結案回報 | Fizz → 老闆 | 完整交付總結、經驗萃取 |

## 4. 違規處置

| 違規行為 | 處置 |
|----------|------|
| Honey 未實地驗證即回報 | Sentry 駁回、計入三振計數 |
| Honey2 計畫書含佔位符/虛假路徑 | Sentry 駁回、計入三振計數 |
| 單方面繞過雙人簽署送審 | Sentry 直接拒絕審查、退回重構 |
| 技能驗收未達硬指標仍宣稱通過 | 視為虛假回報、啟動三振熔斷 |
